## Scope Note (decisões registradas nesta preparação)

1. **Story fora do PRD original, Epic 8 (fecha um gap encontrado na auditoria da Story 5.4).** `POST /profiles` já estava especificado desde a Fase 1 (`docs/architecture.md#REST API Specification`: "Cria perfil CHILD (apelido + faixa etária apenas)") mas nunca foi implementado na Story 1.4 — na época, só o backend de seleção de perfil (`POST /profiles/:id/select`) foi construído, e a criação ficou pendente sem story própria. A Story 5.4 (auditoria de conformidade) registrou isso como achado, sem corrigir (decisão explícita do usuário na ocasião). Agora o usuário pediu para fechar esse gap.
2. **Só `nickname` + `ageRange` são aceitos** — mesma restrição de dados já aplicada em todo o resto do sistema (`CLAUDE.md`: "Perfis CHILD: coletar apenas apelido + faixa etária. Sem sobrenome, foto ou data de nascimento"). O schema zod novo (`CreateChildProfileSchema`) só tem esses dois campos; o teste de conformidade de domínio já existente (`domain-compliance.test.ts`, Story 5.4) continua garantindo que o `model Profile` nunca ganhe campos excedentes.
3. **Só cria perfil CHILD, nunca ADULT** — não existe caso de uso para criar um segundo perfil ADULT pela UI (contas ADULT adicionais são um fluxo de convite/multi-responsável, fora de escopo, nunca mencionado em nenhuma story). O `type` é sempre fixado como `"CHILD"` no backend, nunca aceito como input do cliente.
4. **Perfil ativo CHILD é bloqueado de criar novo perfil (403)** — mesmo padrão de proteção já usado em `ProfilesService.listForUser`/`selectProfile` (SEC-002, Story 1.4): um perfil infantil não deve conseguir gerenciar os perfis da conta. Reaproveita `ProfilesService.isChildProfile` (Story 4.4).
5. **UI: formulário inline na própria tela `/select-profile`** (não uma página nova) — "+ Adicionar perfil" revela um formulário simples (apelido + faixa etária via `<select>` com opções pré-definidas, mesmo padrão de faixas já usado no seed da Story 5.3: "2-4", "4-6", "6-8", "8-10", "10-12"), e a lista é atualizada após a criação. É a tela onde o responsável já está decidindo "quem vai usar agora" — local mais natural para adicionar um novo perfil, sem inventar uma página de "gerenciar conta" que não existe em nenhuma outra story.

## Story

**As a** responsável,
**I want** adicionar um novo perfil de criança pela interface,
**so that** não precisar de acesso direto ao banco de dados para cadastrar meus filhos.

## Acceptance Criteria

1. `POST /profiles` cria um perfil CHILD (`nickname` + `ageRange`) vinculado à conta do usuário autenticado
2. Perfil ativo CHILD não pode criar novo perfil (403)
3. Tela `/select-profile` permite adicionar um novo perfil e o exibe na lista imediatamente após a criação
