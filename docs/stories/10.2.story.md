## Scope Note (decisões registradas nesta preparação)

1. **Story fora do PRD original, Epic 10 (mesmo padrão informal dos Epics 6-9 — sem documento de epic formal).** Segunda story do fatiamento do Epic 10 (ver Story 10.1, item 3, para o fatiamento completo: 10.1 = reconexão trivial, **10.2 = nível + ranking**, 10.3 = "continuar aprendendo").
2. **Depende da Story 10.1**: reaproveita o XP total já buscado por `GET /gamification/xp` na Home (não faz uma segunda chamada só para calcular nível — o nível é derivado localmente a partir do mesmo `total` já em estado no componente).
3. **Ranking só entre perfis `ProfileType.CHILD`** — decisão explícita do usuário ("colegas", não mistura com perfis ADULT). Perfil ativo `ADULT` não participa do ranking; o endpoint retorna `position: null` nesse caso (não é erro, é "não aplicável").
4. **Nível é função pura do XP total, sem schema novo, sem persistência**: `nivel = Math.floor(xpTotal / 200) + 1` (200 XP por nível), barra de progresso = `(xpTotal % 200) / 200 * 100` — valores exatos decididos explicitamente pelo usuário no gate aprovado.
5. **Sem rótulo de faixa ao lado do nível** ("Intermediário"/"Básico"/"Avançado") — nenhuma fonte define os limites dessas faixas; incluir seria invenção (Artigo IV, No Invention). A UI mostra apenas "Nível N".
6. **[AUTO-DECISION]** A fórmula de nível vive em um único lugar — `packages/shared/src/lib/level.ts` (`deriveLevel`) — em vez de duplicada em frontend e backend **(reason: pedido explícito do usuário de "não duplicar a fórmula em dois lugares se puder evitar"; como só o frontend precisa do valor nesta story, centralizar em `packages/shared` deixa o helper pronto para o backend reaproveitar no futuro sem duplicação, sem exigir uma chamada de API nova agora)**.
7. **[AUTO-DECISION]** Empate no ranking é resolvido por `createdAt asc` do perfil (perfil mais antigo fica na posição melhor) **(reason: sem essa ordenação secundária, `Array.prototype.sort` não garante ordem estável entre XPs iguais retornados pelo banco em ordem não determinística; um critério de desempate determinístico e barato evita "flakiness" visual no ranking sem exigir nova coluna ou lógica de negócio)**.
8. **Sem paginação de perfis** — decisão já registrada pelo usuário: volume baixo (ambiente de demo), não otimizar prematuramente. O cálculo carrega todos os perfis `CHILD` em memória.

## Story

**As a** criança usando um perfil ativo,
**I want** ver meu nível real (derivado do meu XP) e minha posição no ranking entre os outros perfis-criança,
**so that** eu enxergue meu progresso relativo de forma simples e sem inventar dados que ninguém definiu.

## Acceptance Criteria

1. Novo endpoint `GET /gamification/ranking` (`JwtAuthGuard`) retorna `{ position: number | null, totalParticipants: number }` — soma de `XpEvent.amount` por `profileId`, apenas perfis `type: CHILD`, ordenados desc (empate resolvido por `createdAt` asc do perfil); `position` é a posição 1-indexed do perfil ativo nesse ranking; se o perfil ativo não é `CHILD`, `position: null` e `totalParticipants` reflete a contagem de perfis `CHILD` existentes (ranking não se aplica a perfis `ADULT`).
2. Sem token de acesso válido, `GET /gamification/ranking` retorna 401; sem perfil ativo selecionado, retorna 403 `NO_ACTIVE_PROFILE` — mesmo padrão de `GET /gamification/xp`/`badges`.
3. `packages/shared` exporta `rankingResponseSchema`/`RankingResponse` (em `gamification.schema.ts`) e um novo módulo `packages/shared/src/lib/level.ts` com `LEVEL_XP_STEP = 200` e `deriveLevel(xpTotal: number): { level: number; progressPercent: number }` (`level = Math.floor(xpTotal / 200) + 1`, `progressPercent = (xpTotal % 200) / 200 * 100`), exportado via `packages/shared/src/index.ts`.
4. Home (`/home`) usa `deriveLevel` sobre o XP total já buscado (`GET /gamification/xp`, Story 10.1) para exibir "Nível {N}" no cabeçalho — sem nenhum rótulo de faixa — e para alimentar a barra de progresso (`ProgressBar`) já existente na seção de topo com o `progressPercent` calculado.
5. Home busca `GET /gamification/ranking` e substitui `jornadaMock.ranking` no StatCard "Ranking" (seção "Sua jornada"): exibe `"{position}º"` quando `position` não é `null`, ou um fallback textual (`"—"`) quando `position` é `null`.
6. `pnpm build` completo do monorepo passa sem erros.
