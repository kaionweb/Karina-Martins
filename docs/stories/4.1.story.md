## Scope Note (decisões registradas nesta preparação)

1. **Sem endpoint HTTP nesta story.** Nenhuma fonte associa uma rota a esta story especificamente — `/ai/chat/en`/`/ai/chat/pt` (`docs/architecture.md#REST API Specification`) pertencem às Stories 4.2/4.3, que adicionam restrição de tema, seleção de modelo por idioma, filtro de conteúdo (4.4) e limite diário (4.5) por cima desta camada. O diagrama de sequência do chat (`docs/architecture.md#Chat de IA em inglês`) mostra a chamada à Anthropic como um passo isolado dentro de um fluxo maior — esta story implementa **só esse passo isolado** (`AiService`), testável diretamente, sem controller. Mesmo padrão já usado nas Stories 1.1/2.1/3.1 (schema/serviço puro, sem endpoint).
2. **Testes usam um client Anthropic mockado, não uma chamada real.** Diferente de toda story anterior (que sempre testou contra o TiDB real, "sem mocks"), a Anthropic é uma **API paga de terceiro**, e `apps/api/.env` local **não tem uma `ANTHROPIC_API_KEY` configurada ainda** (confirmado nesta preparação — só `AI_STREAMING`/`AI_DAILY_LIMIT` existem no `.env` local; `ANTHROPIC_API_KEY` só está declarada, vazia, no `.env.example`). Chamar a API de verdade em todo teste custaria dinheiro a cada execução e tornaria a suíte dependente de uma chave que não existe neste ambiente. O `AiService` recebe o client Anthropic via injeção de dependência (token `ANTHROPIC_CLIENT`), permitindo substituí-lo por um mock do Jest nos testes — a lógica testada é "o serviço chama o SDK corretamente e monta a resposta certo", não "a Anthropic responde corretamente" (isso é responsabilidade da própria Anthropic, fora do controle deste projeto).
3. **`apps/api/test/unit/` é usado pela primeira vez** — a pasta já está prevista em `docs/architecture.md#Test Organization` ("unit/ — Services isolados") especificamente para este tipo de teste (serviço isolado, sem HTTP/banco real), diferente de todas as stories anteriores que só usaram `test/integration/`. Não precisa de configuração nova: `apps/api/jest.config.js` já casa `**/test/**/*.test.ts`, então `test/unit/` já é coberto.
4. **Flag `AI_STREAMING` (AC1) é verificada, não implementada.** A AC pede a chamada não-streamed "atrás de" uma flag — o modo streaming em si não é pedido por nenhuma AC desta story (nem 4.2/4.3 mencionam streaming). `AiService` lança um erro explícito e claro se `AI_STREAMING=true`, em vez de silenciosamente se comportar de forma errada ou inventar suporte a streaming não pedido.
5. **`max_tokens` da chamada à Anthropic é um parâmetro do método, com default `1024`** — nenhuma fonte especifica um valor; é um parâmetro técnico da API da Anthropic (obrigatório em toda chamada), não uma decisão de produto. Deixado configurável para as stories futuras (4.2/4.3) ajustarem se precisarem.
