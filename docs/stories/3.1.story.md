## Scope Note (decisões registradas nesta preparação)

1. **Sem endpoint nesta story.** As ACs pedem só o model e a garantia de que XP é sempre derivado — `GET /gamification/xp` (`docs/architecture.md#REST API Specification`) não é exigido por nenhuma AC desta story. Mesmo padrão já usado nas Stories 1.1/2.1 (schema puro, sem camada de API). O endpoint fica para quando alguma story precisar efetivamente expô-lo (provavelmente Story 3.2, que já mexe em `/lessons/:id/complete` e precisa mostrar "XP total atualizado" na UI).
2. **`Profile` NÃO ganha um campo `xpTotal`.** A AC2 proíbe explicitamente escrita direta em XP total — isso significa que nenhum campo mutável de XP pode existir em `Profile` ou em qualquer outro model; o total é sempre calculado por agregação (`SUM(amount) WHERE profileId = X`) em tempo de leitura, nunca armazenado. Esta story valida essa regra com um teste de agregação real, não apenas documentando a intenção.

## Story

**As a** mantenedor,
**I want** que o XP nunca seja um campo editável diretamente,
**so that** garantir auditabilidade e evitar inconsistência.

## Acceptance Criteria

1. Model `XpEvent` (ledger) registra origem, quantidade e perfil
2. XP total do perfil é sempre a soma dos `XpEvent` — nenhuma escrita direta em `xpTotal`

### Data Models

[Source: docs/architecture.md#XpEvent]

```typescript
export type XpEventSource = "LESSON_COMPLETED" | "STREAK_BONUS" | "BADGE_AWARDED";

export interface XpEvent {
  id: string;
  profileId: string;
  amount: number;
  source: XpEventSource;
  createdAt: string;
}
```

**Relationships:** N:1 com `Profile`. XP total = `SUM(amount) WHERE profileId = X`. [Source: docs/architecture.md#XpEvent]

SQL de referência (autoritativo para a camada de banco): [Source: docs/architecture.md#Database Schema]

```sql
CREATE TABLE XpEvent (
  id        VARCHAR(191) PRIMARY KEY,
  profileId VARCHAR(191) NOT NULL,
  amount    INT NOT NULL,
  source    ENUM('LESSON_COMPLETED','STREAK_BONUS','BADGE_AWARDED') NOT NULL,
  createdAt DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  FOREIGN KEY (profileId) REFERENCES Profile(id) ON DELETE CASCADE,
  INDEX idx_xpevent_profile (profileId)
);
```
