## Scope Note (decisões registradas nesta preparação)

1. **Story fora do PRD original, Epic 7 (nova identidade visual), pedida diretamente pelo usuário** a partir de 6 imagens de referência (mockups de um app concorrente/de terceiros, recebidas via WhatsApp) em `C:\Users\Thiago\Downloads\WhatsApp Unknown 2026-07-28 at 09.54.12\`.
2. **Elementos de propriedade de terceiros dos mockups NÃO são reproduzidos** — personagens/franquias (Paw Patrol, Bluey, Stranger Things, Friends, PJ Masks, Nemo, Divertida Mente, Naruto, Gumball), o nome/marca "km Imersão Conectada" (de outra empresa) e o logotipo específico não entram no projeto. Isso é consistente com a auditoria de conformidade já feita (Story 5.4: "nenhum asset de terceiros no catálogo"). Só a **linguagem visual genérica** (paleta escura+vermelha, layout de cards, bottom nav, tipografia dos widgets de streak/XP) é adotada.
3. **Bug real pré-existente encontrado e corrigido nesta story:** `apps/web/src/app/globals.css` (único CSS efetivamente carregado pelo Next.js) só define `--background`/`--foreground` — as variáveis `--primary`, `--muted`, `--card`, `--accent` etc., referenciadas por praticamente todo componente via `hsl(var(--x))`, **nunca estiveram definidas**, então `background-color`/`color` com esses valores sempre falhavam silenciosamente (propriedade CSS inválida ignorada pelo browser). Isso explica por que botões apareciam sem cor de fundo em todas as verificações manuais anteriores (Stories 6.1/6.2) — não quebrava funcionalidade, só o visual ficava "sem estilo". `packages/ui/src/tokens/theme.css` e `colors.ts` já existiam com um subconjunto de tokens, mas nunca eram importados por `apps/web` (código morto). Corrigido definindo o conjunto completo de tokens (`background`, `foreground`, `card`, `card-foreground`, `primary`, `primary-foreground`, `secondary`, `secondary-foreground`, `muted`, `muted-foreground`, `accent`, `accent-foreground`, `destructive`, `destructive-foreground`, `border`, `ring`) em `globals.css` — fonte de verdade real; `colors.ts`/`theme.css` (`packages/ui`) atualizados para os mesmos valores, como documentação (mesmo padrão de duplicação intencional documentada já aceito na Story 5.3 para `BADGE_DEFINITIONS`, já que `apps/web` não importa CSS de `packages/ui` hoje e adicionar isso seria uma mudança de build fora do escopo de um restyle).
4. **Tema escuro passa a ser o padrão (`:root`), com um bloco `[data-theme="light"]` de override já preparado** (mesmo mecanismo já existente, nenhum toggle de tema é construído — não foi pedido). Cor primária de marca (vermelho) é a mesma nos dois temas.
5. **Bottom nav novo (mobile-first), com só destinos reais** — `Home`, `Catálogo`, `Painel do responsável` (só quando `activeProfile.type === "ADULT"`) e `Sair`. Sem abas "Games"/"IA" (não existem como features próprias) e sem "Perfil" (não existe página de perfil). `lucide-react` (já é dependência de `apps/web`, nunca usado) fornece os ícones.
6. **`/home` reformulado**: saudação + card de streak (`activeProfile.currentStreak`, já disponível no `useProfileStore` desde a Story 6.1, sem chamada nova) + XP total (`GET /gamification/xp`, já existente) + badges + CTA para o catálogo. **Sem** card "continue de onde parou com X% concluído" — não existe rastreio de "última lição acessada" no backend; inventar isso agora seria escopo novo de dado, não de estilo.
7. **Sem filtros de "Nível/Gênero/Habilidade" na busca/catálogo** — `Show` não tem esses campos no schema; adicionar chips de filtro que não filtram nada de verdade seria uma UI enganosa. Fica como possível story futura se esses campos forem modelados de verdade.
8. **Botão "Continuar com Google" adicionado ao `/login`**, apontando para `GET {API_URL}/auth/google` (fluxo OAuth real, já existe desde a Story 1.3, nunca teve botão na UI). **Sem** botão "Continuar com Apple" — nunca foi implementado no backend; adicionar um botão morto seria enganoso.
9. **Landing (`/`) ganha uma checagem de sessão** — se já houver um access token válido (`getAccessToken()`), redireciona para `/select-profile` em vez de mostrar a página de marketing. Necessário para o botão do Google funcionar de ponta a ponta (o callback OAuth redireciona para `WEB_URL` = `/`, que hoje não faz nada com uma sessão já autenticada).

## Story

**As a** usuário da plataforma,
**I want** uma identidade visual coesa (tema escuro, cor de marca, navegação clara),
**so that** a experiência pareça um produto profissional e pronto para demo.

## Acceptance Criteria

1. Tokens de cor completos (não só `background`/`foreground`) definidos e aplicados — nenhum elemento com cor de fundo/texto "quebrada" por variável CSS ausente
2. Navegação inferior fixa com os destinos reais da aplicação (Home/Catálogo/Painel do responsável quando aplicável/Sair)
3. `/home`, `/login`, `/register`, `/select-profile`, `/catalog`, `/catalog/[showId]`, `/lesson/[lessonId]`, `/dashboard`, `/dashboard/transcripts/[profileId]` seguem a nova paleta
4. Nenhum elemento de marca/personagem de terceiros é introduzido
5. Botão "Continuar com Google" funcional em `/login`
