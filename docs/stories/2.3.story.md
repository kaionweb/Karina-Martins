## Scope Note (decisões registradas nesta preparação)

1. **`LessonProgress` ainda não existe no schema** — Story 2.1 criou só `Show`/`Track`/`Lesson`, deixando `LessonProgress` explicitamente para depois (ver `docs/stories/2.1.story.md#Dev Notes`). Esta story cria o model.
2. **O endpoint que MARCA uma lição como concluída (`POST /lessons/{id}/complete`) NÃO está no escopo desta story.** Ele gera `XpEvent` (`docs/architecture.md#REST API Specification`: "Marca lição como concluída e gera XpEvent") — isso é literalmente a Story 3.2 do Epic 3 ("Concessão de XP ao concluir lição"), que ainda nem tem o model `XpEvent` criado. AC3 ("Lições concluídas ficam marcadas visualmente") só pede a **exibição** de um estado já existente — não pede a ação que cria esse estado. Os testes desta story inserem `LessonProgress` diretamente via Prisma (mesmo padrão usado em `packages/database/tests/`), sem depender de um endpoint de conclusão que não existe ainda.
3. **Rotas protegidas ainda não existem (mesma lacuna já registrada na Story 2.2, Scope Note item 1).** `GET /catalog/shows/{id}/tracks`, `GET /catalog/tracks/{id}/lessons` e `GET /lessons/{id}` **exigem token** (sem `security: []` na especificação OpenAPI, diferente de `/catalog/shows` que é público). Sem tela de login, não há como um usuário real obter um token pela UI ainda. Solução adotada: as páginas desta story são **Client Components** (`"use client"`) que usam `getAccessToken()` de `apps/web/src/lib/auth` (já existe, funciona no browser) — tecnicamente corretas e prontas para quando o login existir, mas **não navegáveis ponta-a-ponta por um usuário real agora** (só via um token obtido manualmente, ex: chamando `login()` no console do navegador). Isso também evita, de propósito, o bug de geração estática que quebrou o build da Story 2.2 (ARCH-001): Client Components não são pré-renderizados em build-time com dados de fetch, então não há risco de `next build` tentar chamar a API.
4. **Assume-se 1 trilha por show para fins de navegação da UI**, consistente com o seed de demonstração (`CLAUDE.md`: "2 shows com 1 trilha e 5 lições cada"). A página `/catalog/[showId]` busca as trilhas do show e usa a primeira retornada. Nenhuma AC pede um seletor de trilha para shows com múltiplas trilhas — fora do escopo.
5. **`ShowCard` (Story 2.2) ainda não é clicável** (é uma `<div>`, não um link) — esta story adiciona a navegação de `/catalog` para `/catalog/[showId]`.

## Story

**As a** criança,
**I want** abrir uma trilha e ver suas lições em sequência,
**so that** saber o que fazer a seguir.

## Acceptance Criteria

1. Endpoint retorna lições de uma trilha em ordem
2. UI exibe conteúdo da lição (texto original, sem legendas/letras transcritas de terceiros)
3. Lições concluídas ficam marcadas visualmente

CREATE TABLE LessonProgress (

@UseGuards(JwtAuthGuard)
@Controller("profiles")
export class ProfilesController {
  constructor(private readonly profilesService: ProfilesService) {}

  @Get()

    return this.profilesService.listForUser(req.user);

}
